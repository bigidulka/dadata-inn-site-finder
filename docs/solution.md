# Решение: агентный поиск официального сайта организации

## Цель

По российскому ИНН вернуть домен официального сайта организации либо `null`, когда доказательств недостаточно. Приоритет — точность: ложная привязка чужого домена хуже отсутствующего ответа.

## Общая логика

1. **Разрешение сущности.** Запрос `findById/party` DaData возвращает юридическое наименование, ИНН, ОГРН, адрес и, если есть, исходный web-домен. Эти атрибуты фиксируют, какую именно организацию надо искать, и снижают риск совпадений по похожим названиям.
2. **Поиск кандидатов.** Web Search запускается по юридическому имени, ИНН и фразе «официальный сайт». Из результатов извлекаются домены, URL и snippets. URL нормализуются; домены поисковиков, соцсетей и агрегаторов отбрасываются.
3. **Агентная оценка.** LLM получает только нормализованную карточку организации и ограниченный набор доказательств. Структурированный контракт позволяет выбрать домен или `null`, назвать уверенность и привести supporting URLs.
4. **Детерминированный контроль.** Код принимает решение только если выбранный домен есть среди найденных, не относится к заблокированным платформам, поддержан URL-цитатой и имеет `medium`/`high` confidence. Иначе возвращается `null`.

## Инструменты

- Python 3.11, `requests`;
- DaData `findById/party` — привязка ИНН к юридической сущности;
- Brave Search API — discovery сайтов;
- OpenAI-compatible Chat Completions API — LLM-рецензент доказательств;
- pytest — изолированная проверка контрактов и граничных случаев.

Выбор конкретных LLM/API конфигурируется переменными окружения. Ключи не попадают в код, репозиторий и вывод программы.

## Ограничения и допущения

- Для юридически разных организаций с одним брендом, сайтов холдинга и франшиз ответ принимается только при прямой связи результата с точным ИНН/названием.
- Search snippets могут быть устаревшими. При конфликте данных агент возвращает `null`, а не угадывает.
- Официальный сайт может отсутствовать, быть неиндексируемым либо находиться только в источнике DaData; это нормальный no-match.
- В production полезно сохранять не только результат, но и fingerprint сущности, evidence URLs, confidence и время проверки. Это позволяет периодически переобогащать устаревшие записи и измерять precision/coverage на размеченной выборке.

## Пример

Вход:

```json
{"inn": "7721581040"}
```

Ожидаемый выход:

```json
{"domain": "dadata.ru"}
```

Тесты включают этот сценарий с детерминированными фейками внешних API, а командная строка при реальных ключах выполняет те же шаги против DaData, Brave и выбранного LLM-провайдера.
